# Madu Jakbar Sport

Direktori kegiatan olahraga KPP Madya Dua Jakarta Barat. Dibangun menggunakan Next.js App Router, Tailwind CSS, dan komponen animasi yang sudah ada pada proyek awal.

## Fitur yang disiapkan
- Identitas dan navigasi Madu Jakbar Sport.
- Bagian tujuan komunitas dan tujuh cabang olahraga: Badminton, Running, Panahan, Futsal, Tenis Lapangan, Tenis Meja, e-Sport.
- Pesan Kepala Unit Kerja (redaksi masih berupa draf dan perlu dikonfirmasi sebelum publikasi).
- Form kesan-pesan anggota dengan validasi dasar.
- API dan dashboard cerita anggota yang memuat kiriman terbaru dan memperbarui daftar secara berkala setiap 15 detik.

## Aktifkan dashboard lintas perangkat (Supabase)
Dashboard memerlukan database online. Tanpa konfigurasi ini, formulir tidak akan menyimpan kiriman dan dashboard akan menampilkan pemberitahuan konfigurasi.

1. Buat proyek di Supabase.
2. Buka SQL Editor dan jalankan:

```sql
create table if not exists public.sport_stories (
  id bigint generated by default as identity primary key,
  name text not null check (char_length(name) <= 80),
  sport text not null check (char_length(sport) <= 40),
  activity_date date not null,
  message text not null check (char_length(message) between 8 and 1200),
  created_at timestamptz not null default now()
);

alter table public.sport_stories enable row level security;
create policy "Public can read sport stories" on public.sport_stories
  for select to anon using (true);
create policy "Public can submit sport stories" on public.sport_stories
  for insert to anon with check (
    char_length(name) between 1 and 80 and
    char_length(sport) between 1 and 40 and
    char_length(message) between 8 and 1200
  );
```

3. Pada proyek lokal, buat `.env.local` berdasarkan `.env.example` dan isi `SUPABASE_URL` serta `SUPABASE_ANON_KEY` dari Project Settings → API.
4. Tambahkan dua environment variable yang sama di Vercel (Development/Preview/Production sesuai kebutuhan), lalu redeploy.
5. Uji pengiriman dari dua perangkat/browser berbeda.

### Catatan moderasi dan keamanan
Form ini dibuat untuk kiriman anggota dan kebijakan SQL di atas membuat kiriman dapat langsung dipublikasikan tanpa moderasi. Untuk situs publik resmi, disarankan menambahkan moderasi/admin approval, CAPTCHA atau rate limiting, dan proses autentikasi sebelum dibuka luas. Jangan pernah memasukkan `service_role` key ke variabel publik atau kode browser. Hanya gunakan anon/publishable key dengan kebijakan RLS yang sudah ditinjau.

## Menjalankan lokal
